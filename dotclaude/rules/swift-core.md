# Swift の書き方

Swift を読み書きする時に読み込まれる決まり。保存プロパティのまとめ方・1 行の長さと折り返し・`let` を作る時・警告の扱い・ファイルの名前を決める。

| ほかの決まり | 置き場所 |
| --- | --- |
| ファイルの区画・extension の分け方・空行 | `swift-layout.md` |
| SwiftUI の画面 | `swift-ui.md` |
| テスト | `swift-test.md` |
| 整形で直る決まり | リポジトリの SwiftFormat。設定は最後の節の表に合わせる |

## プロパティのまとまり

保存プロパティは、次の決まりでまとめる。型の本体に置ける物と extension の分け方は、`swift-layout.md` にある。

- 本体と extension の中は、プロパティ・init・関数の順に並べる。
- プロパティ・init・関数のそれぞれの中は、public から private の順に並べる。
- プロパティは、アクセスの範囲が同じものでまとめる。範囲は `public`・`public private(set)`・`private` などである。
- プロパティラッパー（`@State`・`@Environment` など）も、同じものでまとめる。
- `static`・`nonisolated` などの修飾子も、同じものでまとめる。`nonisolated` のものは、同じアクセスの範囲の先頭に置く。
- 保存プロパティは、`var` と `let` でもまとまりを分ける。
- 保存プロパティのまとまり（アクセスの範囲・`var` と `let`・プロパティラッパー）が変わる所には、空行を入れる。`static` は、`static` どうしでまとまりとする。swift-style-check が確かめる。

## 改行

改行は、1 行を 100 字までにし、対象ごとに次の決まりで入れる。折り返せない文字列だけは、100 字を超えてよい。

### 宣言と呼び出しの引数

引数は、数と入れ子で折り返すかを決める。

- 引数が 2 つ以上ある関数とイニシャライザの宣言は、100 字に収まっても引数を 1 行に 1 つずつ書く。
- 引数が 1 つの宣言は、100 字に収まれば 1 行に書く。
- 折り返した引数とモディファイアは、1 行に 1 つずつ並べる。
- 並んで同じ役割をする呼び出しと宣言は、1 つでも折り返したら、ほかも折り返してそろえる。`let` の並びもこれに当たる。
- 100 字に収まる呼び出し・`for`・`where` 句・三項演算子は、折り返さない（次の項を除く）。上の決まりで、並ぶものにそろえる時だけ折り返す。
- 条件に `&&` か `||` がある三項演算子は、100 字に収まっても `?` と `:` の前で折り返す。
- 引数が 1 つの呼び出しは、折り返さない。引数の中の呼び出しを折り返す時だけ、外も折り返す。
- 引数の中の呼び出しの引数が 2 つ以上なら、外も中も 1 行に 1 つずつ折り返す。100 字に収まってもそうする。モディファイアの引数は除く。

### switch とクロージャ

ブロックは、中身が処理かどうかで 1 行に書くかを決める。

- 値を返すだけの `switch` は、`case` を 1 行で書く。代入する時は `=` と同じ行に `switch` を書き、`case` を代入の行と同じ深さにそろえる。
- `case` の中身を次の行から書く時は、`case` の間に空行を入れる。すべての `case` の中身を同じ行に書く `switch` は、続けて書く。
- 中身の無いクロージャは、`{}`・`{ _ in }` と 1 行で書く。
- 処理を行うクロージャと、`defer`・`get`・`set` などのブロックは、中身を改行して書く。値を変えるだけの短いクロージャ（`map` など）は 1 行でよい。
- 末尾のクロージャにプロパティ（`.value` など）をつなぐ時は、閉じ括弧と同じ行に書く（`}.value`）。モディファイアなどの呼び出しをつなぐ時は、閉じ括弧の次の行から 1 行に 1 つずつ並べる。

### 長い式

整形で式の途中が切れる時は、`let` で名前を付けて分ける。swift-style-check が確かめる。三項演算子はモディファイアの引数に入れない。

### 改行の例

処理を行うクロージャと、入れ子の呼び出しは、次の形で書く。

```swift
HomeView(
    model: home,
    onOpenEntry: { id in
        sheet = .edit(id)
    }
)

EntrySheet(
    model: EntryModel(
        database: database,
        date: home.today
    )
)
```

### if と guard の条件

`if` と `guard` の条件は、数で形を変える。条件が 1 つなら 1 行に書く。

```swift
guard let hoge else {
    return
}

if let hoge {
}
```

条件が 2 つ以上の `guard` は、`guard` と `else` をそれぞれ 1 行にし、条件を 1 つずつ並べる。`if` は最初の条件を `if` と同じ行に置き、続きをそろえて並べる。

```swift
guard
    let hoge,
    let foo
else {
    return
}

if let hoge,
   let foo {
}
```

`else if` の条件は、`,` で区切らず 1 つにする。swift-style-check が確かめる。

| 条件 | 書き方 |
| --- | --- |
| 束縛の無い条件が 2 つ以上 | 前に `let` で、`&&` でつないだ名前を付ける |
| 束縛と条件 | 前に `let` で値を出し、束縛の要らない 1 つの条件にする |
| 前に出すと評価の回数や順番が変わる値 | `else if` に入れず、`else` の中に `if` を書く |

```swift
let rests = next == current
    && count >= minimum
let emoji = icon.emoji ?? ""

if let item {
} else if rests {
} else if !emoji.isEmpty {
}
```

## let で名前を付ける値

`let` で名前を付けるかどうかは、次の決まりで決める。

- 引数の中で値を組み立てず、`let` で名前を付けてから渡す。
- 次のものは、引数の中に書いてよい。`Data([...])` のようにリテラルを型に合わせるだけの変換と、SwiftUI の画面の組み立てである。
- 込み入った式は、`let` で名前を付けてから `return` する。
- 1 回しか使わず引数にも渡さない値には、`let` を作らない。メソッドをつなぐ起点や `guard`・`if` の条件は、その場に書く。

## 警告

コンパイラの警告を出さない実装にする。次の決まりで書いて確かめる。

| 場面 | 決まり |
| --- | --- |
| 書く | 足した・変えたコードで警告が出たら、同じ変更の中で直す |
| 隠さない | `@preconcurrency`・`nonisolated(unsafe)`・警告を切る設定で消さない。原因の型や呼び出しを直す |
| 並行性 | `View` の型の中身は MainActor になる。MainActor でない所から呼ぶ static 関数には `nonisolated` を付ける |
| 確かめる | 差分ビルドは、変えていないファイルの警告を出さない。変えたファイルを含めて組み直し、出力の `warning:` が 0 件かを見る |

```sh
xcodebuild build -workspace <workspace> -scheme <scheme> 2>&1 | grep 'warning:' | sort -u
```

## ファイルとフォルダ

ファイルとフォルダは、Xcode とファイルの一覧でアルファベット順に並ぶことを前提に、次の決まりで名前を付ける。

- ファイル名の頭に、元になる型や画面の名前を付け、関係するファイルを隣に並べる。例は `EntryModel`・`EntrySheet`・`Entry+Record` である。
- 同じ役割のファイルは、1 つのフォルダにまとめる。
- 1 つのフォルダには、ファイルかサブフォルダのどちらかだけを入れる。
- フォルダとファイルは増やしすぎない。名前でまとまりが分かる時だけ分ける。
- 1 つのフォルダで頭が同じファイルが 20 本を超えたら、役割の子フォルダに分ける。役割は下の表のとおりで、通し番号のファイルは除く。code-design-check が確かめる。
- 同じ型の拡張だけを置く `Methods` では、`<型>+` の後ろを頭として数える。
- 拡張と、それが返す型のファイルが混ざるフォルダは、`Methods` と `Types` に分ける。どちらも 10 本を超えた時に当てる。兄弟のフォルダが分けていれば、10 本に届かなくても同じ形にそろえる。
- 通し番号のファイルと型は、桁をそろえる。例は `MigrationV001` である。
- 同じファイル名を、別のフォルダやモジュールで使わない。拡張は `+<役割>` で区別する。
- `+` の無いファイルは、同じ名前の型を持つ。`View` の拡張だけを置く、画面ごとのモディファイアのファイルは除く。
- 拡張のファイルの頭は、拡張する型か、その親の型の名前にする。
- 入れ子の型は `.` を抜いてつなぎ、途中の親を省かない。`Wallet.Kind` の拡張は `WalletKind+Title.swift` になる。
- private でない型の名前は、ファイルの名前で始める。拡張のファイルでは、`+` の後ろの役割で始めてもよい。
- 頭をそろえた名前を付けられない小さな型は、private か入れ子にして、使う型のファイルに置く。使う型が 1 つに決まらない時は、別のファイルにする。
- 1 つのファイルが 400 行を超えたら、役割ごとに `<型>+<役割>.swift` へ分ける。
- ファイルの名前と型の名前・ファイルの大きさは、code-design-check が確かめる。
- `project.pbxproj` を手で直す時は、各セクションの項目を ID の順に並べる。
- `UITraitBridgedEnvironmentKey` に適合するキーは、別のファイルに置く。分けないと、SwiftFormat の `environmentEntry` が `@Entry` に書き換えてしまう。

画面を役割の子フォルダに分ける時は、次のとおりにする。

| 子フォルダ | 入れるもの |
| --- | --- |
| `Model` | 画面のモデルと、その拡張 |
| `View` | 画面の本体（`<画面>View`・`<画面>Sheet`）と、その拡張 |
| `Sheet` | 画面から開くシート |
| `Parts` | その画面だけで使う部品。メニューと、シートの中の部品も入れる |
| 流れの名前 | 1 つの流れのファイルが 10 本以上の時だけ置く。流れのモデルも入れる |

## SwiftFormat の設定

リポジトリに SwiftFormat を置く時は、上の決まりに合わせて次のとおりにする。

| 設定 | 値 | 合わせる決まり |
| --- | --- | --- |
| `--max-width` | `100` | 1 行は 100 字まで |
| `--organize-types` | `extension` を含める | 本体と extension の中の並び |
| `--wrap-conditions` | `preserve` | `if` と `guard` の条件の形 |
| `--line-between-guards` | `true` | `swift-layout.md` の、複数行の文の前後の空行 |
| `wrapMultilineFunctionChains` | 外す | 末尾のクロージャにつなぐ呼び出し |
| `blankLineAfterSwitchCase` | 入れる | `case` の間の空行 |
