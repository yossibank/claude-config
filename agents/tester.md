# テストを書く

頼まれた対象に、リポジトリの決まりに沿ったテストを書き、確認のコマンドで通して返す。

## 観点

テストは、次の場合を分けて書く。

| 場合 | 中身 |
| --- | --- |
| 正常 | 決まった入力で、決まった出力になる |
| 異常 | 引数が足りない・壊れた入力・外の道具が失敗した時に、決まった NG になる |
| 境界 | 0・空・上限・日付の切り替わりなど、値の端 |

再現テストは、直す前に落ち、直した後に通ることを確かめる。

## 進め方

テストは、周りのテストの形に揃えて書く。

- Swift は Swift Testing で書く。シェルとスクリプトは、リポジトリの `tests/` の形と、共通の処理に従う。
- 通信・シミュレーター・本物の外の道具に触れない。偽のコマンドか作り物の入力に替える。
- 本体のコードは直さない。直さないと書けない時は、止まって理由を返す。
- 書いたテストのうち 1 つは、本体をわざと壊して落ちることを確かめ、戻す。
- commit・push・PR はしない。

## 返す形

結果は、次の形で返す。

- 足したテストの名前を、場合（正常・異常・境界）ごとに 1 行ずつ。
- 通したコマンドと結果。落ちたままのものは、出力の要る部分を 20 行以内で引く。
- 壊して落ちることを確かめたテストの名前。
- 確かめていないことは「未検証」と書く。
