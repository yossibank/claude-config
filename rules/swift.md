# Swift の書き方

Swift を読み書きするときに読み込まれる決まり。宣言の置き方、名前を付ける値、改行と空行、SwiftUI の画面、ファイルとフォルダ、テストの書き方を決める。リポジトリに SwiftFormat があれば、整形で直る決まりはそちらに任せる。

## 宣言の置き方

型の中身は、次の決まりで置く。

- 型の本体には、保存プロパティと公開する init だけを置く。クラスの指定イニシャライザも本体に置く
- ほかは `public extension`・`extension`・`private extension` の順に分けて置く
- 保存プロパティも公開する init も無い型は、extension に分けず、中身を本体に書く。名前空間の `enum` もこれに当たる。適合も宣言に書き、実装を本体に置く。`private` なものだけ `private extension` に分ける
- メソッドやプロパティを実装する適合は、適合ごとに `extension` を分け、最後に置く
- `Sendable`・`Equatable`・`Hashable`・`Error` のように中身を書かない適合は、宣言に書く
- `View`・`App`・`Widget` などへの適合は宣言に書き、`body` は型の本体の init の後に置く
- 本体と extension の中は、入れ子の型・プロパティ・init・関数の順に並べる。入れ子の型は、置く extension の先頭に置く。SwiftFormat は `--organize-types` に `extension` を含める
- プロパティ・init・関数のそれぞれの中は、public から private の順に並べる
- プロパティは、アクセスの範囲（`public`・`public private(set)`・`private` など）が同じものでまとめる。プロパティラッパー（`@State`・`@Environment` など）も同じものでまとめる。まとまりの間には空行を入れる
- `static`・`nonisolated` などの修飾子も、同じものでまとめる。`nonisolated` のものは、同じアクセスの範囲の先頭に置く
- 保存プロパティは、`var` と `let` でもまとまりを分ける
- 強制アンラップと `precondition` を使わず、正しい値だけを作れる型や init で表す

## 改行

改行は、次の決まりで入れる。

- 1 行は 100 字までにする。SwiftFormat は `--max-width 100` にする
- 引数が 2 つ以上ある関数とイニシャライザの宣言は、100 字に収まっても引数を 1 行に 1 つずつ書く
- 折り返した引数とモディファイアは、1 行に 1 つずつ並べる
- 同じ呼び出しや、並んで同じ役割をする呼び出しと宣言（`let` の並びなど）は、1 つでも折り返したら、ほかも折り返してそろえる
- 引数が 1 つの呼び出しは、折り返さない。引数の中の呼び出しを折り返すときだけ、外も折り返す
- 値を返すだけの `switch` は、`case` を 1 行で書く
- 処理を行うクロージャと、`defer`・`get`・`set` などのブロックは、中身を改行して書く。値を変えるだけの短いクロージャ（`map` など）は 1 行でよい
- 末尾のクロージャにプロパティ（`.value` など）をつなぐときは、閉じ括弧と同じ行に書く（`}.value`）。モディファイアなどの呼び出しをつなぐときは、閉じ括弧の次の行から 1 行に 1 つずつ並べる。SwiftFormat の `wrapMultilineFunctionChains` は外す
- 整形で式の途中が切れるときは、`let` で名前を付けて分ける。三項演算子はモディファイアの引数に入れない
- 折り返せない文字列だけは、100 字を超えてよい
- `if` と `guard` の条件は、下の形で書く。SwiftFormat は `--wrap-conditions preserve` にし、形を変えさせない

処理を行うクロージャと、入れ子の呼び出しは、次の形で書く。

```swift
HomeView(
    model: home,
    onOpenEntry: { id in
        sheet = .edit(id)
    }
)

EntrySheet(
    model: EntryModel(
        database: database,
        date: home.today
    )
)
```

`if` と `guard` の条件は、数で形を変える。条件が 1 つなら 1 行に書く。

```swift
guard let hoge else {
    return
}

if let hoge {
}
```

条件が 2 つ以上なら、`guard` は `guard` と `else` をそれぞれ 1 行にし、条件を 1 つずつ並べる。`if` は最初の条件を `if` と同じ行に置き、続きを揃えて並べる。

```swift
guard
    let hoge,
    let foo
else {
    return
}

if let hoge,
   let foo {
}
```

## let で名前を付ける値

`let` で名前を付けるかどうかは、次の決まりで決める。

- 引数の中で値を組み立てず、`let` で名前を付けてから渡す
- `Data([...])` のようにリテラルを型に合わせるだけの変換と、SwiftUI の画面の組み立ては、引数の中に書いてよい
- 込み入った式は、`let` で名前を付けてから `return` する
- 1 回しか使わず引数にも渡さない値には、`let` を作らない。メソッドをつなぐ起点や `guard`・`if` の条件は、その場に書く

## 空行

空行は、次の決まりで入れる。

- ブロックの中の文は、種類でまとめる。種類は、`let`・`var`・代入・呼び出し・制御文（`guard`・`if`・`for`・`switch`・`do`・`defer`）・`return` に分ける
- 呼び出しには、`await` の文と、結果を捨てる `_ = ...` を入れる。ビューを並べるところも、ビューを呼び出しとして同じ決まりで並べる
- 種類が変わるところには、空行を入れる。同じ種類の 1 行の文どうしの間には、空行を入れない
- `let` は、前の代入の結果を使わないなら、代入より前にまとめる。計算プロパティや副作用を通して使うときも「使う」に入る。確かめられないときは動かさない
- 複数行にわたる文（`let` を含む）があるときは、その前後と `return` の前に空行を入れる
- 型の中のプロパティの宣言も、複数行にわたるものは前後に空行を入れる。1 行の宣言どうしは、空行を入れずにまとめる
- init は、`let` で作る値、プロパティラッパーへの代入（`_model = ...`）、ほかの代入の順に並べ、まとまりの間に空行を入れる
- `guard` が続くときも、`guard` どうしの間に空行を入れる。SwiftFormat は `--line-between-guards true` にする

## SwiftUI の画面

`View` の型は、次の決まりで書く。

- 画面の部品と、処理（`Binding`、保存などの操作、表示用の値の計算）は、別々の `private extension` に分ける。部品の extension を先に置く
- 1 つの要素だけで 1 か所でしか使わない部品（ボタン 1 つ、`Picker` 1 つなど）は、プロパティや関数に分けず `body` に書く
- `#Preview` は、ファイルの最後に置く

## ファイルとフォルダ

ファイルとフォルダは、Xcode とファイルの一覧でアルファベット順に並ぶことを前提に、次の決まりで名前を付ける。

- ファイル名の頭に、元になる型や画面の名前を付け、関係するファイルを隣に並べる（`EntryModel`・`EntrySheet`、`Entry+Record`）
- 同じ役割のファイルは、1 つのフォルダにまとめる
- 1 つのフォルダには、ファイルかサブフォルダのどちらかだけを入れる
- フォルダとファイルは増やしすぎない。名前でまとまりが分かるときだけ分ける
- 頭をそろえた名前を付けられない小さな型は、ファイルに分けず、それを使う型のファイルにまとめる。使う型が 1 つに決まらないときは、別のファイルのままにする。1 つのファイルが大きくなりすぎたら、役割ごとに分ける
- `UITraitBridgedEnvironmentKey` に適合する `EnvironmentKey` は、`EnvironmentValues` の拡張と別のファイルに置く。SwiftFormat の `environmentEntry` に `@Entry` へ書き換えさせない

## テスト

テストは、次の決まりで書く。

- 準備・実行・確認を空行で分ける。`let` が続いて最後の `#expect` が 1 つだけなら、空行を入れない。テストの中では、文の種類でまとめる決まりよりこちらを優先する
- 実行と確認を繰り返すテストは、実行と確認のまとまりごとに空行で区切る
- テストで使う型は `extension` に、テストデータの読み込みは `private extension` に分ける
