# アプリの文書

アプリのリポジトリで、どの事実をどの文書に書くか、文書を足す条件、decisions と画面の仕様の形を決める。spec の中身の役割は、各リポジトリの `.claude/rules/` に書く。

## 書くこと

各文書は、次の役割だけを持つ。

| 文書 | 書く | 書かない |
| --- | --- | --- |
| README | 入口、準備、コマンド、バッジ | 機能の中身、決定 |
| CLAUDE.md | 作業の進め方、このリポジトリだけのコードの書き方、作業と文書の対応 | 全リポジトリ共通の決まり（claude-config） |
| overview | 何を作るか、最初のリリースの機能、守ること、未決 | 作り方 |
| architecture | 今の形（フォルダ、ターゲット、依存、署名の状態） | 理由、選ばなかった案、decisions の決定の言い直し |
| decisions | 決定、理由、選ばなかった案 | 形の詳しい説明（architecture へリンク） |
| data | 表の形と、その決まり | なぜその形か |
| roadmap | 作る順番、状態、画面 | 設定・環境の状態 |
| glossary | 画面の言葉・文書の言葉・コードの型・意味の対応 | 決まりの説明 |

## 足す条件

最初は CLAUDE.md・README・`docs/overview.md`・`docs/roadmap.md` だけを作る。ほかの文書は、次の条件を満たした時に足す。

| 文書 | 足す条件 |
| --- | --- |
| `docs/decisions/<領域>.md` | 迷った案があり、理由を残さないと同じ議論になる決定が出た時 |
| `docs/architecture.md` | 構成が共通の形（`~/Applications/AI/claude-config/docs/architecture-ios.md`）から外れた時。外れた点と、アプリだけの事実（ID、署名の状態など）を書く |
| `docs/data.md` | データベースに表を持った時 |
| `spec/fixtures/` | 計算の決まりがあり、iOS と Android で同じ結果が要る時 |
| `spec/export-format.md` | ユーザーのデータを書き出す・読み込む時 |
| `docs/glossary.md` | 画面の言葉とコードの名前が食い違う語が出た時 |

## 決定の節の形

decisions の節は、決定を太字の 1 行にし、理由と却下した案を表に、細かい決まりを箇条書きに分ける。`**決定：` で探せるように、書き出しをそろえる。

```markdown
## <決定の名前>

**決定：<何をどうするかを 1 行>**

| 項目 | 内容 |
| --- | --- |
| 理由 | … |
| 却下 | … |
| 関連 | <リンク。無ければ行ごと消す> |

決まり：

- <細かい決まりを 1 項目 1 行>
```

## 画面の仕様の形

画面の動きは、段落で書かずに、状態・見た目・操作の表で書く。スクリーンショットがあれば、表の後に `<table>` で横に並べる。置き場所は `docs/images/<画面>-<状態>.png` にする。

```markdown
| 状態 | 見た目 | 操作 |
| --- | --- | --- |
| 収まらない | 2 行目の端を薄くし ⌄ を重ねる | 押すと開く |
| 開いた | 全文と ⌃ | 押すと閉じる |
```
