# Swift の書き方

Swift を読み書きするときに読み込まれる決まり。宣言の置き方、名前を付ける値、改行と空行、ファイルとフォルダを決める。

| ほかの決まり | 置き場所 |
| --- | --- |
| SwiftUI の画面 | `swift-ui.md` |
| テスト | `swift-test.md` |
| 整形で直る決まり | リポジトリの SwiftFormat。設定は最後の節の表に合わせる |

## 宣言の置き方

型の中身は、次の決まりで置く。

- 型の本体には、保存プロパティと公開する init だけを置く。クラスの指定イニシャライザも本体に置く
- ほかは `public extension`・`extension`・`private extension` の順に分けて置く
- 保存プロパティも公開する init も無い型は、extension に分けず、中身を本体に書く。名前空間の `enum` もこれに当たる
- その型の適合は宣言に書き、実装を本体に置く。`private` なものだけ `private extension` に分ける
- メソッドやプロパティを実装する適合は、適合ごとに `extension` を分け、最後に置く
- `Sendable`・`Equatable`・`Hashable`・`Error` のように中身を書かない適合は、宣言に書く
- `View`・`App`・`Widget` などへの適合は宣言に書き、`body` は型の本体の init の後に置く
- 本体と extension の中は、入れ子の型・プロパティ・init・関数の順に並べる。入れ子の型は、置く extension の先頭に置く
- プロパティ・init・関数のそれぞれの中は、public から private の順に並べる
- プロパティは、アクセスの範囲が同じものでまとめる。範囲は `public`・`public private(set)`・`private` などである
- プロパティラッパー（`@State`・`@Environment` など）も、同じものでまとめる。まとまりの間には空行を入れる
- `static`・`nonisolated` などの修飾子も、同じものでまとめる。`nonisolated` のものは、同じアクセスの範囲の先頭に置く
- 保存プロパティは、`var` と `let` でもまとまりを分ける
- 同じまとまりの中では、1 行の宣言を続けて並べ、複数行の宣言の間に挟まない。新しく置くときは、1 行の宣言を先に、複数行の宣言を後に置く
- 強制アンラップと `precondition` を使わず、正しい値だけを作れる型や init で表す

## 改行

改行は、次の決まりで入れる。

- 1 行は 100 字までにする
- 引数が 2 つ以上ある関数とイニシャライザの宣言は、100 字に収まっても引数を 1 行に 1 つずつ書く
- 折り返した引数とモディファイアは、1 行に 1 つずつ並べる
- 並んで同じ役割をする呼び出しと宣言は、1 つでも折り返したら、ほかも折り返してそろえる。`let` の並びもこれに当たる
- 100 字に収まる呼び出し・`for`・`where` 句・三項演算子は、折り返さない。上の決まりで、並ぶものにそろえるときだけ折り返す
- 引数が 1 つの呼び出しは、折り返さない。引数の中の呼び出しを折り返すときだけ、外も折り返す
- 引数の中の呼び出しの引数が 2 つ以上なら、100 字に収まっても、外も中も 1 行に 1 つずつ折り返す。モディファイアの引数は除く
- 値を返すだけの `switch` は、`case` を 1 行で書く。代入するときは `=` と同じ行に `switch` を書き、`case` を代入の行と同じ深さにそろえる
- 中身の無いクロージャは、`{}`・`{ _ in }` と 1 行で書く
- 処理を行うクロージャと、`defer`・`get`・`set` などのブロックは、中身を改行して書く。値を変えるだけの短いクロージャ（`map` など）は 1 行でよい
- 末尾のクロージャにプロパティ（`.value` など）をつなぐときは、閉じ括弧と同じ行に書く（`}.value`）。モディファイアなどの呼び出しをつなぐときは、閉じ括弧の次の行から 1 行に 1 つずつ並べる
- 整形で式の途中が切れるときは、`let` で名前を付けて分ける。三項演算子はモディファイアの引数に入れない
- 折り返せない文字列だけは、100 字を超えてよい
- `if` と `guard` の条件は、下の形で書く

処理を行うクロージャと、入れ子の呼び出しは、次の形で書く。

```swift
HomeView(
    model: home,
    onOpenEntry: { id in
        sheet = .edit(id)
    }
)

EntrySheet(
    model: EntryModel(
        database: database,
        date: home.today
    )
)
```

`if` と `guard` の条件は、数で形を変える。条件が 1 つなら 1 行に書く。

```swift
guard let hoge else {
    return
}

if let hoge {
}
```

条件が 2 つ以上なら、`guard` は `guard` と `else` をそれぞれ 1 行にし、条件を 1 つずつ並べる。`if` は最初の条件を `if` と同じ行に置き、続きを揃えて並べる。

```swift
guard
    let hoge,
    let foo
else {
    return
}

if let hoge,
   let foo {
}
```

## let で名前を付ける値

`let` で名前を付けるかどうかは、次の決まりで決める。

- 引数の中で値を組み立てず、`let` で名前を付けてから渡す
- 次のものは、引数の中に書いてよい。`Data([...])` のようにリテラルを型に合わせるだけの変換と、SwiftUI の画面の組み立てである
- 込み入った式は、`let` で名前を付けてから `return` する
- 1 回しか使わず引数にも渡さない値には、`let` を作らない。メソッドをつなぐ起点や `guard`・`if` の条件は、その場に書く

## 空行

空行は、次の決まりで入れる。

- 1 行の文が 3 つまでのブロックは、空行を入れずに続けて書く。種類が変わっても入れない。init の本体は除く
- それより長いブロックの文は、種類でまとめる。種類は `let`・`var`・代入・呼び出し・制御文・`return` である
- 制御文は `guard`・`if`・`for`・`switch`・`do`・`defer` である
- 呼び出しには、`await` の文と、結果を捨てる `_ = ...` を入れる
- 種類が変わるところには、空行を入れる。同じ種類の 1 行の文どうしの間には、空行を入れない
- `super` の呼び出しと、元の delegate に渡す呼び出しは、短いブロックでも、ほかの文と空行で分ける
- `let` は、前の代入の結果を使わないなら、代入より前にまとめる。計算プロパティや副作用を通して使うときも「使う」に入る。確かめられないときは動かさない
- 複数行にわたる文（`let` を含む）があるときは、その前後と `return` の前に空行を入れる
- 並んで同じ役割をする代入と呼び出しは、1 つでも複数行にわたるなら、すべての間に空行を入れる。`let` の並びは除く
- 型の中のプロパティの宣言も、複数行にわたるものは前後に空行を入れる。1 行の宣言どうしは、空行を入れずにまとめる
- init は、`let` で作る値、プロパティラッパーへの代入、ほかの代入の順に並べる。まとまりの間に空行を入れる
- プロパティラッパーへの代入は `_model = ...` の形である
- `guard` が続くときも、`guard` どうしの間に空行を入れる

短いブロックと `super` は、次の形で書く。

```swift
var palette: ThemePalette {
    let isDark = colorScheme == .dark
    return look.palette(isDark: isDark)
}

override func didMoveToWindow() {
    super.didMoveToWindow()

    observeStyle()
    apply()
}
```

## ファイルとフォルダ

ファイルとフォルダは、Xcode とファイルの一覧でアルファベット順に並ぶことを前提に、次の決まりで名前を付ける。

- ファイル名の頭に、元になる型や画面の名前を付け、関係するファイルを隣に並べる。例は `EntryModel`・`EntrySheet`・`Entry+Record` である
- 同じ役割のファイルは、1 つのフォルダにまとめる
- 1 つのフォルダには、ファイルかサブフォルダのどちらかだけを入れる
- フォルダとファイルは増やしすぎない。名前でまとまりが分かるときだけ分ける
- 頭をそろえた名前を付けられない小さな型は、ファイルに分けず、それを使う型のファイルにまとめる。使う型が 1 つに決まらないときは、別のファイルのままにする。1 つのファイルが 400 行を超えたら、役割ごとに `<型>+<役割>.swift` へ分ける
- `project.pbxproj` を手で直すときは、各セクションの項目を ID の順に並べる
- `UITraitBridgedEnvironmentKey` に適合するキーは、別のファイルに置く
- 分けないと、SwiftFormat の `environmentEntry` が `@Entry` に書き換えてしまう

## SwiftFormat の設定

リポジトリに SwiftFormat を置くときは、上の決まりに合わせて次のとおりにする。

| 設定 | 値 | 合わせる決まり |
| --- | --- | --- |
| `--max-width` | `100` | 1 行は 100 字まで |
| `--organize-types` | `extension` を含める | 本体と extension の中の並び |
| `--wrap-conditions` | `preserve` | `if` と `guard` の条件の形 |
| `--line-between-guards` | `true` | `guard` どうしの間の空行 |
| `wrapMultilineFunctionChains` | 外す | 末尾のクロージャにつなぐ呼び出し |
