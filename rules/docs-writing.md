# 文書の書き方

`.md` を読み書きするときに読み込まれる決まり。運用、文、表現、README と CLAUDE.md の形を決める。文書ごとの役割は `rules/docs-roles.md` にある。リポジトリだけの文書の役割は、各リポジトリの `.claude/rules/` にある。

> [!IMPORTANT]
> 文書には**今の状態だけ**を書く。経緯は git の履歴に任せる。

## 運用

文書を今の状態に保つために、次の決まりを守る。

| 決まり | 中身 |
| --- | --- |
| 書き換える | 事実が変わったら、その箇所を書き換える。末尾への追記や「以前は〜」で済ませない |
| 1 つの事実は 1 か所 | ほかの文書はリンクで指す。例外は README のバッジだけ |
| 書く前に探す | 事実を書く前に、同じ語を grep で探す。見つかったら書き足さず、そこへリンクする |
| 消す | 使わなくなった節・表の行・図は消す。空の見出しを残さない |
| 書かない | 外のツールの事情、決まりの言い換え。決まりと今の事実だけを書く |
| 決まっていないこと | 「未決」と書く。決まったら書き換えて「未決」を消す |
| 確かめていないこと | `[!WARNING]` にまとめる。確かめたら本文に結果を書き、WARNING から消す |

## 文と見出し

文と見出しは、次の決まりで書く。

| 決まり | 中身 |
| --- | --- |
| 文体 | 常体（「である」「する」）で書く。敬体（です・ます）を混ぜない |
| 結論を先に | 文書の最初の 1 文で、その文書に何があるかを書く |
| 一文を短く | 60 字を超えたら、句点で区切れないか見直す。一文の論点は 1 つにする |
| 見出し | 見出しだけで中身がつかめる言葉にする。同じ階層で同じ名前を使わない |
| 見出しの間 | 見出しと、そのすぐ下の小見出しの間に、1 文以上の本文を置く |
| 箇条書きの前置き | 箇条書きの前に、何の一覧かが分かる文を置く。「次のとおり」だけで済ませない |
| 一覧の数 | 一覧の前置きに、項目の数（「次の 3 つ」）を書かない |
| 英数字 | 日本語と英数字の間に半角スペースを入れる |

## 表現

表現は、内容に合わせて次のように使い分ける。

| 表現 | 使う | 使わない |
| --- | --- | --- |
| 表 | 2 つ以上の属性を持つ項目の比較。書くことの無いセルは空のままにする | 単純な一覧（箇条書きにする） |
| 箇条書き | 単純な一覧、手順 | 1〜2 項目（文で書く） |
| Mermaid の図 | 依存の向き、処理の流れ、表どうしの関係 | 表で足りるもの |
| グラフ | 数値のデータがあるとき。Mermaid の `xychart` か `pie` で描く | 数値がないとき |
| フォルダの木 | フォルダ構成 | ファイルの一覧だけのとき（箇条書きにする） |
| 太字 | 守らないと壊れることの短い語句。1 節に 1 か所まで | 文全体。意味を太字だけで伝えること |
| 斜体 | なし | すべて |
| 絵文字 | 言葉だけでは見分けにくいものに、言葉と並べて 1 つ。使う絵文字は下の表 | 節の見出し、飾り。絵文字だけで意味を伝えること |
| アラート | 本文から分けて目立たせたい注意。種類は下の表 | 本文の言い換え。続けて並べること。1 節に 2 つ以上 |
| 画像 | README の見た目の紹介。alt を付ける。2 枚以上は `<table>` で横に並べ、列に見出しを付ける | docs、rules、CLAUDE.md。`<img>` を縦に続けて並べること |
| HTML | README の画像の大きさ・並び・ダークモードの切り替え（`<img>`・`<table>`・`<picture>`）。Mermaid のラベルの改行（`<br/>`） | 中央寄せ（`<div align="center">`）など、見た目だけのもの |
| バッジ | README の冒頭の、変わりにくい事実。並べ方は下の表 | 進み具合など、よく変わるもの。ライブラリの版 |

### 絵文字の種類

絵文字は、次の表にあるものだけを使う。

| 分類 | 絵文字 |
| --- | --- |
| 状態 | ✅ 完了、🚧 作業中、⬜ 未着手 |
| OS・役割 | 🍎 iOS、🤖 Android、🧩 共通 |

### バッジの並び

バッジは shields.io で作り、状態と技術の段に分けて並べる。段の間は空行で分け、無い段は作らない。

| 段 | 並び | 書き方 |
| --- | --- | --- |
| 状態 | CI → リリース → ライセンス | 動的なバッジ。CI は `label=Verify&logo=github` を付ける |
| 技術 | 対応 OS → 言語 → 主な技術 | 固定のバッジ。版は対応 OS と言語だけに書き、技術は名前だけにする |

技術の段のバッジには、Simple Icons のロゴとブランドの色を付け、`logoColor=white` にする。ロゴが無い技術は、近いロゴを使う。技術の一覧を、バッジとは別に文字で並べない。

### アラートの種類

アラートは、伝えることの重さで使い分ける。

| 種類 | 使う時 |
| --- | --- |
| `NOTE` | 補足 |
| `TIP` | こつ |
| `IMPORTANT` | 守らないといけないこと |
| `WARNING` | 危ないこと、確かめていないこと |
| `CAUTION` | 壊れる操作、戻せない操作 |

## README の形

README は、次の順に書く。無い節は作らない。

| 順 | 節 | 中身 |
| --- | --- | --- |
| 1 | 冒頭 | タイトル（`#`。種類の絵文字を 1 つ付けてよい）、何のリポジトリかの 1 文、バッジ、スクリーンショット |
| 2 | 文書 | docs の一覧 |
| 3 | 中身の節 | 構成、用語、評価など、リポジトリごとの説明 |
| 4 | 動かし方 | 要る道具とコマンド。ライブラリは「使い方」 |
| 5 | そのほかの節 | リリース、出典など |

## CLAUDE.md の形

各リポジトリの CLAUDE.md は、次の順に書く。無い節は作らない。

| 順 | 見出し | 中身 |
| --- | --- | --- |
| 1 | 見出しなしの冒頭 | 何のリポジトリかを 1 文で |
| 2 | 作業の進め方 | 確認のコマンド、作業の手順 |
| 3 | コードの書き方 | このリポジトリだけの書き方 |
| 4 | 構成 | 置き場所の決まり、依存の向き |
| 5 | そのほかの節 | ほかのリポジトリとの取り決め、リポジトリだけの文書の役割など |

ここと共通の CLAUDE.md にある決まりは、各リポジトリに書かない。
