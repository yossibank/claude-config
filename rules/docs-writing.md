# 文書の書き方

`.md` を読み書きするときに読み込まれる決まり。運用、文、表現、読み手ごとの形を決める。アプリの文書ごとの役割は `rules/docs-app.md` にある。

> [!IMPORTANT]
> 文書には**今の状態だけ**を書く。経緯は git の履歴に任せる。

## 運用

文書を今の状態に保つために、次の決まりを守る。

| 決まり | 中身 |
| --- | --- |
| 書き換える | 事実が変わったら、その箇所を書き換える。末尾への追記や「以前は〜」で済ませない |
| 1 つの事実は 1 か所 | ほかの文書はリンクで指す。例外は README のバッジだけ |
| 書く前に探す | 事実を書く前に、同じ語を grep で探す。見つかったら、そこへリンクする |
| 消す | 使わなくなった節・表の行・図は消す。空の見出しを残さない |
| 書かない | 外のツールの事情、決まりの言い換え |
| 決まっていないこと | 「未決」と書く。決まったら書き換えて「未決」を消す |
| 確かめていないこと | `[!WARNING]` にまとめる。確かめたら本文に結果を書き、WARNING から消す |

## 読み手で分ける

文書は、読み手で形を変える。どちらも、文字を並べるだけにせず、見出し・表・箇条書きで形を作る。

| 読み手 | 文書 | 形 |
| --- | --- | --- |
| 人 | README、`docs/`、`spec/` | 見出しの絵文字、アラート、図、バッジで目立たせる |
| Claude | CLAUDE.md、`rules/`、`SKILL.md`、`agents/` | 絵文字と飾りを使わない。決まった節の並びと表で読ませる |

## 文と見出し

文と見出しは、読み手によらず次の決まりで書く。

| 決まり | 中身 |
| --- | --- |
| 文体 | 常体（「である」「する」）で書く。敬体を混ぜない |
| 結論を先に | アプリの `docs/`・`spec/` は、タイトルの直後の `[!NOTE]` に分かることを書く。3 行までと関連文書のリンクにする |
| 冒頭の 1 文 | ほかの文書は、最初の 1 文で何があるかを書く |
| 一文を短く | 一文は 60 字までにし、超えたら句点で区切る。コードとパスも字数に数える |
| 段落を短く | 1 つの段落と箇条書きの 1 項目は 3 文まで、表のセルは 2 文までにする |
| 長い説明 | 3 文を超える説明は、手順なら番号付きの箇条書き、比べるものなら表にする |
| 見出し | 見出しだけで中身がつかめる言葉にする。同じ階層で同じ名前を使わない |
| 目次 | GitHub が作るので、手で書かない |
| 見出しの間 | 見出しと、そのすぐ下の小見出しの間に、1 文以上の本文を置く |
| 一覧の前置き | 何の一覧か見出しで分かれば、前置きを書かない。書くときも、項目の数を書かない |
| 用語 | `docs/glossary.md` があれば、その言葉を使う。型がある語は、初めに型名を `コード` で添える |
| 英数字 | 日本語と英数字の間に半角スペースを入れる |

## 表現

表現は、内容に合わせて次のように使い分ける。

| 表現 | 使う | 使わない |
| --- | --- | --- |
| 表 | 2 つ以上の属性を持つ項目の比較。書くことの無いセルは空にする | 単純な一覧 |
| 箇条書き | 単純な一覧、手順 | 1〜2 項目（文で書く） |
| Mermaid の図 | 依存の向き、処理の流れ、表どうしの関係、状態の移り変わり、画面の移動 | 表で足りるもの |
| グラフ | 数値のデータ。Mermaid の `xychart` か `pie` で描く | 数値がないとき |
| フォルダの木 | フォルダ構成。木には名前だけを書き、説明は表に分ける | ファイルの一覧だけのとき |
| 太字 | 決定・結論の 1 行。守らないと壊れることの短い語句 | 1 節に 2 か所以上。文全体 |
| 斜体 | なし | すべて |
| アラート | 本文から分けて目立たせたい注意。種類は下の表 | 本文の言い換え。1 節に 2 つ以上 |
| 画像 | README の見た目の紹介、docs の画面の仕様。alt に要点を書く | Claude が読む文書。本文の代わり |
| HTML | 画像の並び（`<img>`・`<table>`・`<picture>`）。長い補足を畳む `<details>` | 中央寄せなど、見た目だけのもの |

冒頭の `[!NOTE]` は、アラートの数に入れない。決定や決まりは `<details>` に畳まない。

### アラートの種類

アラートは、伝えることの重さで使い分ける。

| 種類 | 使う時 |
| --- | --- |
| `NOTE` | 補足 |
| `TIP` | こつ |
| `IMPORTANT` | 守らないといけないこと |
| `WARNING` | 危ないこと、確かめていないこと |
| `CAUTION` | 壊れる操作、戻せない操作 |

## 人が読む文書の飾り

README と `docs/`・`spec/` は、見出しと絵文字で目で追える形にする。

### 見出しの絵文字

`##` の見出しは、すべての頭に絵文字を 1 つ付けるか、どれにも付けない。README には付ける。節の中身に近いものを、次の表から選ぶ。

| 節 | 絵文字 |
| --- | --- |
| 全体像、構成 | `🗺️` |
| 文書 | `📚` |
| 動かし方、入れ方、使い方 | `🚀` |
| 決まり、書き方 | `📏` |
| 名前の付け方 | `🏷️` |
| 仕組み、フック | `🪝` |
| スキル、道具 | `🧰` |
| スクリプト | `📜` |
| エージェント | `👷` |
| 設定、環境変数 | `🔧` |
| 確認、テスト | `🧪` |
| 画面 | `📱` |
| データ | `🗄️` |
| 注意 | `⚠️` |

### 本文の絵文字

本文の絵文字は、言葉と並べて 1 つだけ使う。次の表のものに限る。

| 分類 | 絵文字 |
| --- | --- |
| 状態 | `✅` 完了、`🚧` 作業中、`⬜` 未着手 |
| OS・役割 | `🍎` iOS、`🤖` Android、`🧩` 共通 |
| 重さ | `🔴` 高、`🟠` 中、`🟡` 低、`⚪` 無し |

### バッジの並び

バッジは shields.io で作り、状態と技術の段に分けて並べる。段の間は空行で分け、無い段は作らない。

| 段 | 並び | 書き方 |
| --- | --- | --- |
| 状態 | CI → リリース → ライセンス | 動的なバッジ。CI は `label=Verify&logo=github` を付ける |
| 技術 | 対応 OS → 言語 → 主な技術 | 固定のバッジ。版は対応 OS と言語だけに書く |

技術のバッジには、Simple Icons のロゴとブランドの色を付ける。`logoColor=white` にし、ロゴが無い技術は近いロゴを使う。技術の一覧を、バッジとは別に文字で並べない。

## Claude が読む文書の形

CLAUDE.md・rules・SKILL.md・agents は、飾りを使わずに、決まった並びで読ませる。

| 決まり | 中身 |
| --- | --- |
| 飾り | 絵文字と画像を使わない |
| 冒頭 | タイトルの直後の 1 文で、読み込まれる時と決めることを書く |
| 決まり | 守ることは表か箇条書きにし、例はその後のコードブロックに置く |
| コマンド | 文の中に長いコマンドを書かない。コードブロックに出し、文では名前で呼ぶ |

### SKILL.md の節

SKILL.md の `##` は、次の順に並べる。中身の無い節は作らない。

| 順 | 節 | 中身 |
| --- | --- | --- |
| 1 | 起動条件 | description で足りない、使う時と使わない時 |
| 2 | 入力 | 引数と、決まっている前提 |
| 3 | 手順 | 番号付きの手順と、走らせるコマンド |
| 4 | 手順の詳細 | スクリプトがすること、表の読み方など。名前は中身に合わせる |
| 5 | 報告 | 人に返すもの |
| 6 | 制約 | してはいけないこと |

「手順」と「報告」は、どの SKILL.md にも置く。agents の `##` は、最後を「返す形」にする。

## README の形

README は、次の順に書く。無い節は作らない。

| 順 | 節 | 中身 |
| --- | --- | --- |
| 1 | 冒頭 | タイトル、何のリポジトリかの 1 文、バッジ、スクリーンショット |
| 2 | 文書 | docs の一覧 |
| 3 | 中身の節 | 構成、用語、評価など、リポジトリごとの説明 |
| 4 | 動かし方 | 要る道具とコマンド。ライブラリは「使い方」 |
| 5 | そのほかの節 | リリース、出典など |

## CLAUDE.md の形

各リポジトリの CLAUDE.md は、次の順に書く。無い節は作らない。

| 順 | 見出し | 中身 |
| --- | --- | --- |
| 1 | 見出しなしの冒頭 | 何のリポジトリかを 1 文で |
| 2 | 作業の進め方 | 確認のコマンド、作業の手順 |
| 3 | コードの書き方 | このリポジトリだけの書き方 |
| 4 | 構成 | 置き場所の決まり、依存の向き |
| 5 | そのほかの節 | ほかのリポジトリとの取り決め、リポジトリだけの文書の役割など |

ここと共通の CLAUDE.md にある決まりは、各リポジトリに書かない。

## 守らせる仕組み

決まりのうち文字で分かるものは、仕組みで止める。

| 仕組み | 見ること |
| --- | --- |
| `hooks/docs-check.py` | 一文と段落の長さ、表のセル、絵文字、見出し、HTML、斜体、英数字の間 |
| `scripts/config-audit.py` | SKILL.md と agents の節の並び、README の表、リンク |
