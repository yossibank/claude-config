# 文書の書き方

`.md` を読み書きする時に読み込まれる決まり。どの文書にも共通の運用・文・表現を決める。読み手ごとの形は、下の「読み手で分ける」の表のファイルにある。

> [!IMPORTANT]
> 文書には**今の状態だけ**を書く。経緯は git の履歴に任せる。

## 運用

文書を今の状態に保つために、次の決まりを守る。

| 決まり | 中身 |
| --- | --- |
| 書き換える | 事実が変わったら、その箇所を書き換える。末尾への追記や「以前は〜」で済ませない |
| 1 つの事実は 1 か所 | ほかの文書はリンクで指す。例外は README のバッジだけ |
| 書く前に探す | 事実を書く前に、同じ語を grep で探す。見つかったら、そこへリンクする |
| 消す | 使わなくなった節・表の行・図は消す。空の見出しを残さない |
| 書かない | 外のツールの事情、決まりの言い換え |
| 決まっていないこと | 「未決」と書く。決まったら書き換えて「未決」を消す |
| 確かめていないこと | `[!WARNING]` にまとめる。確かめたら本文に結果を書き、WARNING から消す |

## 読み手で分ける

文書は、読み手で形を変える。どちらも、文字を並べるだけにせず、見出し・表・箇条書きで形を作る。

| 読み手 | 文書 | 形 | 決まり |
| --- | --- | --- | --- |
| Claude | CLAUDE.md、`rules/`、`SKILL.md`、`agents/`、`output-styles/` | 飾らず、決まった節の並びと表で読ませる | `rules/docs-claude.md` |
| 人 | README、`docs/`、`spec/` | 見出しの絵文字・アラート・図・バッジで目立たせる | `rules/docs-human.md` |

## 文・見出し・用語

文・見出し・用語は、読み手によらず次の決まりで書く。

### 文

文は、短く区切って書く。

| 決まり | 中身 |
| --- | --- |
| 文体 | 常体（「である」「する」）で書く。敬体を混ぜない |
| 一文を短く | 一文は 60 字・読点 3 つまでにし、超えたら句点で区切る。コードとパスも字数に数える |
| 段落と項目 | 1 つの段落と箇条書きの 1 項目は、3 文までにする |
| 項目の文末 | 文の項目は句点で終え、語句だけの項目には付けない。1 つの一覧の中では、どちらかにそろえる |
| 表のセル | 表のセルは、2 文までにする。1 つのセルに別々の指示を入れない |
| 長い説明 | 3 文を超える説明は、手順なら番号付きの箇条書き、比べるものなら表にする |
| 一覧の前置き | 何の一覧か見出しで分かれば、前置きを書かない |
| 項目の数 | 一覧の前置きに、項目の数を書かない |
| 英数字 | 日本語と英数字の間に半角スペースを入れる |

### 見出し

見出しは、目で追うための言葉にする。

| 決まり | 中身 |
| --- | --- |
| 言葉 | 見出しだけで中身がつかめる言葉にする |
| 名前 | 同じ階層で同じ名前を使わない |
| 目次 | 節の名前を並べただけの目次は書かない。GitHub が作る |
| 見出しの間 | 見出しと、そのすぐ下の小見出しの間に、1 文以上の本文を置く |

### 用語

用語は、文書とコードで同じものを指すようにそろえる。

| 決まり | 中身 |
| --- | --- |
| 言葉 | `docs/glossary.md` があれば、その言葉を使う |
| 型名 | 型がある語は、初めに型名を `コード` で添える |

## 表現

表現は、内容に合わせて次のように使い分ける。

| 表現 | 使う | 使わない |
| --- | --- | --- |
| 表 | 2 つ以上の属性を持つ項目の比較。書くことの無いセルは空にする | 単純な一覧。2 列の表で、1 列目に同じ値が繰り返す時 |
| 箇条書き | 単純な一覧、手順 | 1〜2 項目は文で書く（チェックリストと番号付きの手順を除く） |
| Mermaid の図 | 依存の向き、処理の流れ、表どうしの関係、状態の移り変わり、画面の移動 | 表で足りるもの |
| グラフ | 数値のデータ。Mermaid の `xychart` か `pie` で描く | 数値がない時 |
| フォルダの木 | フォルダ構成。木には名前だけを書き、説明は表に分ける | ファイルの一覧だけの時 |
| 太字 | 決定・結論の 1 行。守らないと壊れることの短い語句 | 1 節に 2 か所以上。文全体 |
| 斜体 | なし | すべて |
| アラート | 本文から分けて目立たせたい注意。種類は下の表 | 本文の言い換え。冒頭の `[!NOTE]` を除いて 1 節に 2 つ以上 |
| 画像 | README の見た目の紹介、docs の画面の仕様。alt に要点を書く | Claude が読む文書。本文の代わり |
| HTML | 画像の並び（`<img>`・`<table>`・`<picture>`）。長い補足を畳む `<details>` | 中央寄せなど、見た目だけのもの。決定や決まりを畳む `<details>` |

### アラートの種類

アラートは、伝えることの重さで使い分ける。

| 種類 | 使う時 |
| --- | --- |
| `NOTE` | 補足 |
| `TIP` | こつ |
| `IMPORTANT` | 守らないといけないこと |
| `WARNING` | 危ないこと、確かめていないこと |
| `CAUTION` | 壊れる操作、戻せない操作 |

## 守らせる仕組み

決まりのうち文字で分かるものは、仕組みで止める。ここに無い決まりは、仕組みでは見ていない。

### 文書の検査

`hooks/docs-check.py` は、`.md` を Edit・Write した後に走るフックである。config-audit は、`make audit` で追跡している全 `.md` に同じ検査をかける。決まりごとに、それぞれが見ることは次のとおりである。

| 決まり | docs-check | config-audit |
| --- | --- | --- |
| 運用 | | リンク先とパスの参照先、リンク先の見出しがあるか |
| 文の長さ | 一文の長さと読点の数、段落・項目・表のセルの文の数 | |
| 一覧の前置き | 前置きの項目の数 | |
| 項目の文末 | 中に句点がある項目の末尾、1 つの一覧の中のそろえ方 | |
| 文体と英数字 | 敬体の文末、日本語と英数字の間。敬体は、コードの囲み・引用・インラインコードの中を除く | |
| 冒頭 | タイトルの直後の 1 文か `[!NOTE]`、冒頭の `[!NOTE]` の行数 | |
| 見出し | 見出しと小見出しの間の本文、同じ親の下の同じ名前の見出し | |
| 目次 | 手で書いた目次、節の名前を並べた 2 列の表と文 | |
| 用語 | | `docs/development.md` のそろえる語の表の、使わない語 |
| 箇条書き | 1〜2 項目の箇条書き。チェックリストと番号付きの手順を除く | |
| 表 | 2 列の表の、1 列目の同じ値の繰り返し。理由と却下の行を重ねる `docs/decisions/` は除く | |
| 太字・アラート・斜体 | 1 節の太字とアラートの数、アラートの種類、斜体 | |
| コードと木 | コードブロックの言語、フォルダの木の説明 | |
| HTML と大きさ | README と `docs/` の外の HTML、使ってよいタグ、`docs/` の 1 ファイルの大きさ | |
| 絵文字 | 見出しの絵文字の数と位置、Claude が読む文書の絵文字、本文の絵文字の表 | |
| 人が読む文書の見出し | README と `docs/`・`spec/` の `##` の絵文字が、付いているか、表にあるか、重なっていないか。`docs/decisions/` はそろっているか | |
| バッジと README | バッジの段の並び、状態の段が動的なバッジか、README の節の順 | |
| Claude が読む文書 | 文の中の長いコマンド | rules の `paths`、ひな形の CLAUDE.md の節の順 |
| SKILL.md | | 「手順」と「報告」の有無、固定の節の順、ほかの節の置き場所、番号付きの手順。description の文末と字数 |
| agents | | `name`・`model` と最後の「返す形」。本文に「書き換えない」とある agents の `tools` |

### config-audit が見るほかのこと

`scripts/config-audit.py` は、文書の検査のほかに次を見る。

- ひな形の Makefile と `.sh` が呼ぶ claude-config のファイルがあるか
- ひな形の `__<名前>__` の印が、`replace-placeholders.py` の tokens にあるか
- `replace-placeholders.py` が、`__<名前>__` のほかを置き換えていないか
- skills・agents・rules・hooks・scripts が README の表にあるか
- フック・scripts・スクリプトを持つスキルと `tests/` のテストが 1 対 1 か
- スキルが README の使う順の図にあるか
- 名前の接頭語とスキルのスクリプトの頭の動詞が、`docs/development.md` の表にあるか
- `.sh` の頭の `set`、`.sh` の中の Python、`assert`、ワークツリーの置き場所の直書き
- 編集を受けるフックの matcher
