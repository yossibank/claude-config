# 手直しから決まりを直す

人の手直しを材料に、決まりの改定案を出す手順。同じ指摘を 2 回受けないように、指摘を決まりか仕組みに移す。

## 入力

材料は、次のコマンドで集める。

```sh
python3 -I ${CLAUDE_SKILL_DIR}/scripts/collect.py <YYYY-MM>
```

`collect.py` は、次の材料を出す。

- `~/.claude/projects/*/memory/` の、種類が `feedback` のメモリ
- その月の会話で人が送った、400 字以下の文。手直しの言葉（「ではなく」「外して」「戻して」「毎回」など）を含むものだけを出す。1 件は、その言葉の前後 120 字に切る
- 決まりの効き目。その月の会話とサブエージェントの会話から、リポジトリごとに次の回数を数える
  - リポジトリは、Edit・Write したファイルと、Bash の `git -C` の先で決める。無ければ会話の場所にする
  - Edit・Write の回数
  - `hooks/pre-edit-load-rules.py` が、当たる rules を読まずに編集しようとして止めた回数
  - `hooks/bash-check-edits.py` が、Bash でファイルを書き換えたと返した回数
  - `hooks/pre-bash-check-pr.py` が、確認を通す前の push と PR の作成を止めた回数
  - 失敗して動かなかったフックの、多いもの 5 件。消えた作業場所で失敗したものは、フックのせいではないので数えない

## 手順

改定案は、次の順に作る。

1. 決まりの効き目を見る。下の表に当たるものは、手直しより先に案にする。

   | 効き目 | 案 |
   | --- | --- |
   | 動かなかったフックがある | フックの登録か、フックのファイルを直す。動かないフックの決まりは、何も守らせていない |
   | 決まりを読まずに編集した回数が多い | その場所で使うスキルとエージェントの手順に、当たる rules を読む段を足す |
   | Bash で書き換えた回数がある | 書き換えたスキルやスクリプトの手順を、Edit・Write を使う形に直す |
   | 確認の前の push・PR がある | その場所で push している手順を、pr-create を通す形に直す |

2. 手直しの材料を仕分ける。アプリの機能や見た目への注文は外し、Claude の作り方・書き方・進め方への手直しだけを残す。
3. 残ったものを、同じ指摘ごとにまとめる。
4. まとまりごとに、今の決まりを探す。
   - claude-config の CLAUDE.md・`rules/`・`skills/`・`agents/`
   - アプリの CLAUDE.md・`.claude/rules/`
5. 下の表で、案の種類を決める。
6. 案を人に見せ、選んでもらう。
7. 選ばれた案だけを、作業の区切りで直す。決まりに移したメモリは消す。

| 今の決まり | 指摘の回数 | 案 |
| --- | --- | --- |
| 無い | 2 回以上か、feedback のメモリがある | 決まりを足す。どのアプリでも同じなら claude-config、アプリだけならアプリのリポジトリ |
| 無い | 1 回 | 案にしない。次の月にまた見る |
| ある | 1 回以上 | 文を短く強くするか、フックやスクリプトで止める仕組みにする。重なるメモリも消す |
| ある（メモリと重なる） | 0 回 | メモリを消す案にする |

メモリが、名前の変わったファイルや無くなった決まりを指している時は、直すか消す案にする。

## 報告

人には、次の形の表で返す。案は 5 件までにし、効き目の案を先に、手直しの案は指摘の回数が多い順に並べる。

| 案 | 種類 | 直す先 | 根拠 |
| --- | --- | --- | --- |
| 決まりの文の案 | 足す・強める・仕組みにする・メモリを消す・フックを直す | ファイルのパス | 指摘の日付と回数、メモリの名前、フックの回数 |
