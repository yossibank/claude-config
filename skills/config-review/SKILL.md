# claude-config を調べ直す

claude-config の全体を観点ごとに調べ、台帳に無い改善だけを出す手順。台帳は `docs/improvements.md` にある。台帳と機械の検査で、同じ指摘を繰り返さない。

## 起動条件

claude-config の改善点や直せる所を聞かれた時に使う。1 つの PR の差分の確認には使わず、pr-create のレビューに任せる。

## 手順

調べる・確かめる・残すの順に進め、直すのは人が案を選んでからにする。

1. `docs/improvements.md` を読む。載っている項目は、新しい指摘にしない。
2. `make verify` を走らせる。NG があれば、調べる前に報告する。
3. `git ls-files` の出力を、下の「観点と分け方」の表で分ける。
4. 観点ごとにエージェントを 1 つずつ並べて走らせる。渡すものは「エージェントに渡すもの」にある。
5. 返ってきた読んだファイルの一覧を、観点のファイルと比べる。読み漏れがあれば、そのファイルだけを読み直させる。
6. 指摘の行を自分で読み、事実と違うものと台帳にあるものを外す。
7. 同じ種類の指摘が 3 件以上あれば、docs-check か config-audit の検査にする案を添える。
8. 人に報告し、直す案を選んでもらう。
9. 選ばれなかった指摘を、台帳の「残っている改善」に足す。

## 観点と分け方

| 観点 | ファイル | 見ること |
| --- | --- | --- |
| 人が読む文書 | `README.md`、`docs/`、ひな形の `.md` | 文書の構成、区切れる長い文、表・図・アラートにできる所 |
| Claude が読む文書 | `CLAUDE.md`、`rules/`、`skills/*/SKILL.md`、`agents/`、`output-styles/` | 読み違える文、決まりどうしやコードとの食い違い |
| 名前と並び | 全部のファイルの名前、`settings/`、README の表 | 接頭語と動詞、並べる順、同じ中身の重なり |
| 処理 | `hooks/`、`lib/`、`scripts/`、`skills/*/scripts/` | バグ、黙って落ちる所、重なった処理、遅い所 |
| テスト | `tests/` | 分岐の抜け、利用者の環境に左右される所 |

## エージェントに渡すもの

エージェントには、次のものを渡す。探させずに、読むファイルを決めて渡す。

| 渡すもの | 中身 |
| --- | --- |
| 読むファイル | その観点のファイルの一覧。全部を読ませ、読んだファイルの一覧を返させる |
| 先に読む決まり | `docs/development.md` と、観点に当たる `rules/` |
| 外すもの | 台帳の項目と、`rules/docs-core.md` の「守らせる仕組み」の検査が見ていること |
| 件数 | 上限を付けない。重さの低いものも返させる |
| 返す形 | 1 件ごとに、重さ・`ファイル:行`・今の形・直す案 |

## 報告

人には、重さの高い順に並べた表で返す。台帳に既にあって外した件数と、検査にする案も添える。

| 重さ | 観点 | 場所 | 中身 | 直す案 |
| --- | --- | --- | --- | --- |

## 制約

- 調べる間は、台帳のほかのファイルを書き換えない。
- 選ばれた案を PR で直したら、同じ PR で台帳の行を消す。
- 直さないと人が決めた指摘は、理由と一緒に台帳の「直さないと決めたこと」に移す。
