# 不具合を調べて直す

不具合を、再現してから仮説で調べ、原因を確かめてから直す手順。直す時の決まりは、共通の CLAUDE.md の「不具合を直す」に従う。

## 起動条件

落ちる・動かない・見た目がずれる時に使う。作りたい機能の相談や、振る舞いを変えない整理には使わない。

## 入力

| 入力 | 中身 |
| --- | --- |
| `$ARGUMENTS` | 症状、ログやスタックトレース、怪しいファイル。省いたら人に聞く |
| 確認のコマンド | リポジトリの CLAUDE.md にある確認のコマンド |

## 手順

調べる段と直す段を分け、間で人の承認を得る。

1. 症状を、期待した振る舞いと実際の振る舞いの 2 行にまとめる。
2. 再現する。再現できない時は、要る道具・手順・許可を人に求めて止まる。
3. 「仮説の立て方」に沿って、仮説を 3 つ立てる。
4. 仮説ごとに `debugger` を呼び、証拠を集めさせる。3 つは並べて呼んでよい。
5. 返った証拠から、原因を 1 つに決める。決まらない時は、足りない証拠を集めて 3 に戻る。
6. 原因・直し方・再現テストの案を報告し、人の承認を得る。
7. 承認されたら、再現テストを先に書き、落ちることを確かめる。テストは `tester` に任せてよい。
8. 直して、再現テストと確認のコマンドを通す。

## 仮説の立て方

仮説は、互いに重ならない 3 つにする。次の表の別々の行から選ぶと重なりにくい。

| 分類 | 例 |
| --- | --- |
| 入力とデータ | 想定外の値、空、形の違うデータ、古い保存データ |
| 状態と順序 | 初期化の順、二重の呼び出し、競合、画面の行き来 |
| 環境 | OS の版、端末の大きさ、権限、外の道具の版 |
| 変更 | 最近の commit、依存の更新、設定の変更 |

1 つの仮説には、正しければ見つかるはずのものを 1 つ添える。`debugger` には、仮説とそれを渡す。

## 報告

手順の 6 と、直した後に、次を返す。

| 時 | 返すもの |
| --- | --- |
| 6 | 症状の 2 行、再現の手順、仮説ごとの判定、原因、直し方の案、再現テストの案 |
| 直した後 | 直したファイル、再現テストの名前、通した確認、外して消した変更 |

確かめていないことは「未検証」と書く。

## 制約

再現と原因の確認の前に、直し始めない。6 の承認の前に、本体のコードを書き換えない。
